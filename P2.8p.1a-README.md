# P2.8p.1a — Finisher Effect Choice Fix

Correctif patch-only de P2.8p.1.

## Correction

Un effet `effects.finisher` est une **option de conversion**, pas un effet déjà
déclenché. Une réussite de Finisher ne l'ajoute donc plus automatiquement à
`pendingEffects`.

Exemple : **Frappe de rupture**
- la carte continue d'afficher Rupture dans le message de Conversion ;
- le joueur choisit dégâts OU Rupture (critique : dégâts ET Rupture) ;
- `rupture-vulnerable` n'est plus créé en `pending` simplement parce que
  l'attaque a réussi.

`pendingEffects` reste réservé aux effets réellement déclenchés qui attendent
leur timing, par exemple **Guidage du Finisher** après utilisation du Support.

## Nettoyage du test précédent

Le `rupture-vulnerable` déjà présent appartient à l'ancien Engagement fermé.
Le prochain Opener remet `pendingEffects` à `[]`.

## Test ciblé

1. Nouvel Opener.
2. Support `Guidage du Finisher`.
3. `api.engagementState.pendingEffects()` doit contenir
   `finisher-attack-bonus` / `next-finisher-attack` / `pending`.
4. Lancer le Finisher.
5. Le chat doit rappeler le +1d6 et l'effet doit passer `consumed`.
6. Si le Finisher est `Frappe de rupture`, Rupture doit être proposée dans le
   message de Conversion mais **ne doit pas apparaître automatiquement** dans
   `pendingEffects`.

# P2.10k.4 — Autorité MJ + Sol + drag depuis Notes

## Problème corrigé

Un joueur pouvait déplacer visuellement une entrée entre les conteneurs, mais
`expeditionManifest.save()` tentait ensuite d'écrire directement dans le
stockage World. Le joueur n'a pas cette autorité.

Cette passe fait du MJ connecté l'autorité d'écriture pour les mutations
d'inventaire demandées par un joueur.

## Flux

### Paquetage → Sol / FOB / Caravane

1. Le joueur démarre le drag d'une entrée du paquetage.
2. Le client envoie une demande socket.
3. Le MJ recharge le manifest persistant.
4. Le MJ vérifie que le joueur a accès à la source **et** à la destination.
5. Le MJ appelle la primitive `expeditionManifest.transfer`.
6. Le MJ valide et sauvegarde le manifest.
7. Tous les clients ouverts rechargent la nouvelle révision.

Un joueur ne peut donc pas utiliser le client pour atteindre le sac d'un autre
joueur ou un conteneur partagé désactivé.

### Notes d'un monstre → Sol

Les liens Foundry `data-uuid` pointant vers un Item sont rendus draggables par
le Toolkit. Le drop transmet l'UUID de l'Item au MJ.

Le MJ résout l'Item et utilise `expeditionItems.acquire()`, ce qui conserve le
snapshot Foundry et passe par les mêmes règles/capacités que le paquetage.

Cela permet notamment de glisser `Cuir de Tetsucabra` ou `Croc de Tetsucabra`
depuis les Notes du Tetsucabra vers **Sol**.

## Précondition

Le `module.json` doit toujours contenir :

```json
"socket": true
```

et un MJ doit être connecté pour valider une mutation demandée par un joueur.

## Vérification structurelle

```powershell
powershell -ExecutionPolicy Bypass `
  -File ".\tools\verify-p2.10k.4.ps1"
```

## Test runtime

1. Ouvrir la fenêtre de paquetage côté MJ et côté joueur.
2. Côté joueur, glisser un objet du sac vers **Sol**.
3. Vérifier qu'aucune erreur de sauvegarde World n'apparaît.
4. Vérifier que l'objet disparaît du sac et apparaît au Sol chez les deux clients.
5. Ouvrir le Tetsucabra et son onglet Notes.
6. Glisser `Cuir de Tetsucabra` ou `Croc de Tetsucabra` sur une case libre du Sol.
7. Vérifier que l'objet est créé dans le Sol et synchronisé chez le MJ.
8. Désactiver l'accès joueur au Sol côté MJ : le même dépôt doit être refusé.

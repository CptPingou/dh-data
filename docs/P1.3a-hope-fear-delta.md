# P1.3a — Hope & Fear delta census

P1.2 closes the **SRD 2.0 canonical baseline**, not the full Daggerheart corpus.

P1.3 therefore resumes source extraction before any Foundry adapter work.

## Roadmap now locked

**P1.3a — Hope & Fear corpus/delta census**  
Classify H&F sections against SRD 2.0. SRD-covered mechanical entities are not duplicated by default.

**P1.3b — Hope & Fear deep private delta**  
Deep-diff the four H&F campaign frames and private appendix/reference assets. Extract only private mechanics/content needed by the user's database.

**P1.3c — Other campaign-setting inventory**  
Register each additional campaign frame/setting source before extracting it.

**P1.3d — Other campaign-setting extraction**  
Extract mechanics and data with source/version provenance.

**P1.4 — Primitive Census**  
Every observed mechanic is decomposed into candidate reusable primitives. Each primitive must cite concrete occurrences in official/private/playtest/homebrew corpora.

**P1.5 — Primitive Coverage Test**  
Attempt to express SRD 2.0, H&F private deltas, other campaign settings, Blood Hunter, and Monster Hunter using the primitive vocabulary. Any recurring special-case code is evidence of a missing primitive.

**P1.6 — Multi-corpus integrity audit**  
Validate IDs, provenance, variants, references, private/public boundaries, and primitive coverage.

Only then:

**P2 — Foundryborne Primitive Module + adapters**  
Foundryborne becomes a runtime/UX target for the proven primitive vocabulary, not the source of the ontology.

## Why this matters

The database is now also an empirical census of Daggerheart's mechanical language. This is what will tell us which generic building blocks a Foundryborne homebrew module actually needs: resources, tracks, slots, recipes, upgrades, state transitions, segmented adversaries, result tables, travel graphs, faction relationships, campaign mechanics, play aids, and whatever additional primitives the corpus demonstrates.

P1.3a is deliberately conservative: it inventories and classifies. It does not copy proprietary H&F text into the SRD tree.

# P2.11c.4a2 — Actions Artillery à partir de specimens natifs

## Constat après 4a1

Les flags d'automatisation persistaient, mais les trois cartes avaient toujours
`actions: 0`. Cela montre que le problème n'était pas simplement Array vs Object.

## Correctif

Le Toolkit ne construit plus l'ActionField Foundryborne à la main.

À l'import il cherche dans `dh-domain-cards` une Action déjà valide provenant
d'une carte non-Artillery, la clone, puis remplace uniquement les champs
sémantiques nécessaires à la carte Artillery.

Même principe pour l'effet `prone` quand un specimen est disponible.

La forme du conteneur `system.actions` (Array ou Object) est elle aussi détectée
sur les cartes réelles du runtime et reproduite.

Cela évite de dépendre d'une hypothèse sur le schéma interne de Foundryborne
2.9.4.

localiser précisément la couche restante sans nouvelle supposition.

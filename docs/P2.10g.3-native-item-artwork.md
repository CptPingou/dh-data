# P2.10g.3 — Native item artwork mapping

Objectif : réutiliser les icônes natives de Foundryborne tout en conservant
`dh-data` comme source de vérité.

Les images ne sont pas copiées dans le module. Les JSON du toolkit reçoivent
le chemin natif `systems/daggerheart/...`.

## 1. Déployer le code puis exporter le mapping dans Foundry

Après robocopy + F5 :

```js
const api = game.modules.get("daggerheart-campaign-toolkit").api;

api.nativeItemArtwork.status();
await api.nativeItemArtwork.export();
```

Foundry télécharge :

`native-item-artwork-map.json`

Le mapping contient `id`, `name`, `img`, `uuid` et le pack natif de chaque item.

## 2. Appliquer dans dh-data

Copier le fichier téléchargé dans le dépôt, par exemple à la racine, puis :

```powershell
python .\tools\apply_native_item_artwork.py .\native-item-artwork-map.json --dry-run
```

Contrôler les compteurs `updated/unmatched`.

Puis :

```powershell
python .\tools\apply_native_item_artwork.py .\native-item-artwork-map.json
```

Cibles :
- `data/core/fr/dh-weapons.json`
- `data/core/fr/dh-armor.json`
- `data/core/fr/dh-consumables.json`
- `data/core/fr/dh-loot.json`

Matching :
1. `flags.daggerheart-campaign-toolkit.mechanicsReconstruction.nativeId`
2. ancien `artworkSource.nativeId`
3. nom natif conservé dans les flags
4. nom courant en dernier recours

Chaque item reçoit aussi :

```json
"flags": {
  "daggerheart-campaign-toolkit": {
    "artworkSource": {
      "kind": "foundryborne-native",
      "pack": "daggerheart.consumables",
      "nativeId": "...",
      "nativeName": "...",
      "path": "systems/daggerheart/...",
      "matchedBy": "nativeId"
    }
  }
}
```

## 3. Reconstruire les compendia

Après robocopy :

```js
const api = game.modules.get("daggerheart-campaign-toolkit").api;
await api.syncAutonomousSources();
await api.autonomousSourceStatus();
```

Les compendia FR utilisent alors directement les assets natifs Foundryborne.

# P2.11d.2a — Hotfix ItemLink Artificier

## Cause confirmée

Les features Artificier étaient bien créées dans `dh-features`, mais
`Artificier.system.features` résolvait encore les Items du Blood Hunter.

Le specimen Foundryborne est un ItemLink runtime de forme observable :

```text
{ item: DhItem, type, uuid }
```

`item` est une référence résolue runtime. Un simple `deepClone()` du specimen
pouvait conserver la liaison au document du specimen.

## Correctif

- sérialiser le specimen via `toObject()` / `_source` avant remapping ;
- supprimer toute propriété runtime `item` ;
- remplacer explicitement `uuid` par `doc.uuid` ;
- conserver les fallback `itemUuid`, `value`, `id`, `itemId` ;
- vérifier avant retour que `uuid === doc.uuid`.

La correction est générique et couvre classes et sous-classes.

## Test runtime

Réimporter :

```js
const hb = await import(
  `/modules/daggerheart-campaign-toolkit/scripts/pilot-import.mjs?v=${Date.now()}`
);
await hb.importArtificerArtillery();
```

Puis :

```js
const classPack =
  game.packs.get("daggerheart-campaign-toolkit.dh-classes");
const classes = await classPack.getDocuments();
const artificer = classes.find(i =>
  i.flags?.["daggerheart-campaign-toolkit"]?.sourceId ===
  "homebrew.artificer.class.artificer"
);

artificer.system.features.map(link => ({
  type: link.type,
  uuid: link.uuid,
  item: link.item?.name
}));
```

# P2.10k.1 — Droits des conteneurs côté joueur

## Règle joueur

Un joueur voit uniquement :

1. son propre `backpack`, s'il n'est pas `stored` ;
2. un conteneur partagé ayant :
   - `presentation.playerRole` = `fob`, `caravan` ou `ground`
   - `presentation.playerAccess` = `true`.

Tous les autres conteneurs sont retirés de la vue joueur.

L'identification du sac personnel utilise en priorité le personnage assigné
à `game.user.character`, puis les droits OWNER comme fallback.

## Administration MJ

L'onglet MJ contient maintenant une section :

`Accès joueurs aux conteneurs partagés`

Chaque conteneur non-backpack peut recevoir un rôle joueur :

- Masqué
- FOB
- Caravane
- Sol

et un booléen `Accès joueur`.

La sauvegarde incrémente la révision du manifest et réutilise le socket déjà
mis en place en j.6c. Les clients joueurs ouverts rechargent donc immédiatement
leur vue.

## Pourquoi `presentation.playerRole`

Le schéma actuel valide les `container.type` contre une liste fermée. Pour ne
pas rendre les manifests existants invalides, `Sol` est ici un rôle fonctionnel
d'accès, stocké dans `presentation.playerRole = "ground"`, sans modifier le
`container.type` structurel.

Une migration de schéma vers un vrai type `ground` pourra être faite plus tard
si on décide qu'il doit porter des règles mécaniques propres.

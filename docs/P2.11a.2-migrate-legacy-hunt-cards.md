# P2.11a.2 — Migration des 17 cartes Chasse legacy

Ce jalon ne redessine aucune carte. Il migre le corpus existant qui était
temporairement enregistré dans `valor` vers le domaine custom `hunt`.

## Corpus attendu

Appui défensif, Conversion, Couverture, Cuistot, Diversion, Extracteur,
Feinte d’approche, Frappe d’épuisement, Frappe de rupture,
Frappe mutilante, Guidage du finisher, Naturaliste, Ouverture,
Ouverture précise, Provocation, Tacticien, Traqueur.

## Étape 1 — audit puis migration des SOURCES

Le repo reste la source de vérité.

Audit seulement :

```powershell
cd C:\dev\dh-data
python .\tools\migrate-p2.11a.2-hunt-sources.py --root .
```

Attendu : `[AUDIT GREEN]` avec 17/17.

Puis seulement si GREEN :

```powershell
python .\tools\migrate-p2.11a.2-hunt-sources.py --root . --apply
```

Le script refuse d’écrire si une carte est absente, dupliquée dans les
sources ou possède un domaine autre que `valor`/`hunt`.

Il ne change ni les noms, ni les sourceIds, ni les mécaniques. Il change le
domaine `valor -> hunt` et remplace uniquement une éventuelle icône Valor
par l’icône Chasse temporaire.

## Étape 4 — migration du compendium existant

Console MJ :

```js
const mh = await import(
  `/modules/daggerheart-campaign-toolkit/scripts/pilot-import.mjs?v=${Date.now()}`
);

await mh.migrateLegacyHuntCards();
```

Cette migration conserve les documents existants : `_id`, sourceId, actions,
effects, descriptions, niveaux et recall costs ne sont pas recréés. Seul
`system.domain` passe de `valor` à `hunt` (plus l’icône temporaire si elle était
l’icône Valor).

Contrôle :

```js
await mh.huntMigrationStatus();
```

Attendu : `green: true`, `expected: 17`, `found: 17`, `hunt: 17`.

`Lecture de la proie` reste séparée : c’est la carte pilote P2.11a.1 et elle
n’entre pas dans les 17 cartes legacy.

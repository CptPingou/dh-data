# P2.10h.2b — Retour partiel Backpack → Actor

Le runtime confirme que `unloadToActor()` supporte déjà une quantité :

```js
unloadToActor(manifest, {
  containerId,
  entryId,
  quantity = null,
  note = null
})
```

et que `expeditionManifestApi.extract(... quantity: qty)` décrémente
l'entrée correctement.

Le patch ajoute donc uniquement la sélection de quantité lorsque :

- `quantity == null` ;
- l'entrée contient plus d'une unité.

## Résultat attendu

```text
Backpack : Objet ×5
Retour au personnage
Quantité : 2

Actor    : Objet ×2
Backpack : Objet ×3
```

Règles :

- quantité `1` : pas de dialogue ;
- `0` / valeur négative : refus ;
- valeur supérieure au stock depuis le dialogue : bornée au stock ;
- annulation : aucun changement ;
- l'API explicite conserve son erreur `quantity-exceeds-entry` si un
  appelant lui passe directement une quantité supérieure au stock.

Aucun monkey-patch de `api.expeditionItems` n'est utilisé.

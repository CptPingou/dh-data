# P2.11c.1b — Fix ItemLink specimens

## Symptôme

L'import arrivait jusqu'au linkage des features de classe puis échouait avec :

`Aucun ItemLink specimen disponible pour hope.`

## Cause

Le code cherchait la forme d'un `ItemLink` dans un **template de classe vide**.
Sous Foundryborne 2.9.4, ce template ne contient pas forcément d'entrée
`system.features`, donc il n'existe aucun specimen `hope` à cloner.

Ce n'est pas une absence de Hope Feature : les classes déjà présentes dans
`dh-classes` ont bien des liens de type `hope` et `class`.

## Correctif

Le mapping prend désormais ses specimens directement dans les documents
déjà valides des compendiums Toolkit :

- `dh-classes` pour `hope` et `class`
- `dh-subclasses` pour `foundation`, `specialization`, `mastery`

On clone uniquement la **forme du lien**, puis on remplace sa référence par
l'UUID / ID de la feature Artificier correspondante.

Le fallback vers le template vide est conservé pour compatibilité future.

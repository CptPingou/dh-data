# P1.4 — Primitive Census

P1.4 does **not** design the Foundry module yet. It establishes an empirical
vocabulary of reusable mechanics from the normalized corpus.

The census distinguishes three levels:

- **data primitives** — tags, linked entities, structured references;
- **mechanical primitives** — resources, tracks, states, slots, transitions,
  thresholds, recipes, procedures, travel, faction relations, etc.;
- **runtime/UI primitives** — play aids and map/handout bindings.

Each candidate keeps its concrete source evidence. A primitive becomes
interesting when it recurs across corpora rather than only once in one setting.

## Important constraint

This pass does not fabricate Monster Hunter evidence from conversational memory.
If no normalized Monster Hunter/Chasse file is present in `data/`, that corpus
is explicitly deferred to the P1.5 coverage test.

The Homebrew Kit remains design guidance: it can constrain what a valid
homebrew primitive should support, but it is not silently treated as playable
rules content.

## Run

From `C:\dev\DH Data>`:

```bat
python tools\build_primitive_census.py
```

Outputs:

```text
data/primitive-census/primitive-census.json
data/primitive-census/primitive-evidence.json
data/registry/P1.4-status.json
```

A GREEN result means the current normalized corpus yields a non-trivial,
cross-corpus primitive vocabulary suitable for the next step.

P1.5 then performs the stricter test: can SRD 2.0, Hope & Fear, Blood Hunter,
Monster Hunter/Chasse, and future settings actually be expressed without
special-case runtime code?

# P2.10h.1f — Remplacement du dialog d'expédition

Symptôme de P2.10h.1e :
- nouvelle fenêtre correctement à jour ;
- ancienne fenêtre toujours visible.

Cause :
`HTMLDialogElement.close()` ferme le dialog mais ne supprime pas son nœud DOM.
Le renderer d'expédition crée ensuite un nouveau dialog.

Correction :
1. `close()` si le dialog est ouvert ;
2. `remove()` systématique ;
3. attendre un `requestAnimationFrame` ;
4. rouvrir avec le manifest frais complet.

## Multijoueur

Ce patch ne rend pas encore le workflow multi-client autoritaire.

Le refresh DOM est local au client qui effectue l'action. Pour la phase
multijoueur, le transfert devra passer par un handler GM/serveur autoritaire
qui :
- valide droits, quantité, capacité et révision ;
- modifie Actor + manifest ;
- persiste une seule transaction logique ;
- diffuse un événement aux clients ;
- chaque client rafraîchit son dialog ouvert localement.

Ce travail relève du rail multi-PJ / multi-container (P2.10k), avec une
première sécurisation possible avant si les joueurs doivent manipuler leur
sac directement pendant les tests.

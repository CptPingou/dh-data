# P2.10i.3 — Archivage des états terminaux

## Principe

Les entrées `consumed` et `deleted` peuvent être retirées de
`container.contents` sans perdre leur historique.

Elles sont déplacées vers :

```js
manifest.metadata.expeditionItemArchive
```

Une entrée archivée conserve :

- `archiveId`
- `archivedAt`
- container source
- état terminal
- `entry` complet, donc `entryId`, snapshot et lifecycle history

## API

```js
api.expeditionItems.listArchive(manifest)

api.expeditionItems.archiveTerminal(manifest, {
  containerId,
  entryIds,
  note
})

api.expeditionItems.purgeArchive(manifest, {
  archiveIds,
  states,
  note
})
```

## Sécurité

Aucune purge automatique.

`archiveTerminal()` ne sélectionne que les entrées dont le lifecycle est
`consumed` ou `deleted`.

`purgeArchive()` est une action distincte et volontaire.

## Restitution

La future restitution de fin d'expédition pourra travailler sur
`container.contents` pour les objets actifs/modifiés/legacy et consulter
l'archive séparément pour l'audit des consommations/suppressions.

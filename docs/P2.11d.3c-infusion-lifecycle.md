# P2.11d.3c — Cycle de vie et incidents des Infusions

## Autonomie du porteur

Le joueur Artificier n'a pas besoin d'être connecté, ni son token présent : le
registre vit sur son Actor de répertoire, référencé par le MJ. L'équipement du
porteur reste entièrement utilisable sans l'Artificier. Les opérations qui
modifient le registre sont faites par un utilisateur ayant les droits sur cet
Actor (typiquement le MJ). **Ce lot ne crée pas d'effet autonome directement sur
l'Item et n'automatise pas des bonus non documentés.**

## Contrat source

- L'Artificier crée ses infusions au repos court ou long via l'API 3b existante.
- Elles expirent au repos long de l'Artificier.
- Lorsqu'un porteur subit des **dégâts provenant d'une réussite critique**,
  lancer 1d6 : 1 perte de l'infusion la plus récente portée par ce personnage ;
  2 marquer 1 PV ; 3 marquer 1 Stress ; 4–6 aucun effet.
- Le porteur peut dépenser **1 Espoir, une fois par session**, pour prévenir
  l'incident. L'Espoir est dépensé manuellement sur sa fiche avant l'appel
  `prevent:true,confirmedHopeSpent:true` ; l'API trace la consommation.

**Aucune détection automatique de critique ou de repos** : les événements et
chemins des ressources natives Daggerheart 2.10.6 n'ont pas encore été
contractuellement validés. Les changements PV / Stress / Espoir sont effectués
par le joueur ou le MJ sur la fiche native ; le résultat API les indique sans
mutation incertaine de champs système.

## Test / usage MJ

```js
const { artificerInfusionApi: inf } = await import(
 `/modules/daggerheart-campaign-toolkit/scripts/artificer-infusion-runtime.mjs?v=${Date.now()}`
);
const artificer = game.actors.get('ID_DE_L_ARTIFICIER');
const porteur = game.actors.get('ID_DU_PORTEUR');
console.log(inf.newestForRecipient(artificer, porteur));
console.log(inf.status(artificer));
```

Lorsqu'un **dégât critique a effectivement été subi**, jeter 1d6 normalement et
remplacer le résultat dans l'appel suivant :

```js
await inf.resolveCriticalDamage(artificer, porteur, {
 confirmedCriticalDamage: true,
 dieResult: 1
});
```

Pour prévenir l'incident, dépenser d'abord 1 Espoir sur la fiche du porteur,
puis :

```js
await inf.resolveCriticalDamage(artificer, porteur, {
 confirmedCriticalDamage: true,
 dieResult: 1,
 prevent: true,
 confirmedHopeSpent: true
});
```

`consequence` renvoie : `infusion-lost`, `mark-1-hp-manually`,
`mark-1-stress-manually`, `none` ou `prevented`. L'ordre est chronologique,
filtré sur **les infusions portées par le personnage touché**, pas tous les PJ.

Début d'une nouvelle session (ne retire **pas** les infusions) :

```js
await inf.startNewSession(artificer, {confirmed:true});
```

Repos long de l'Artificier (fait expirer ses infusions sur **tous** les porteurs) :

```js
await inf.clearAtLongRest(artificer, {confirmed:true});
```

## Limites / étape suivante

Le MJ doit posséder les droits d'écriture sur l'Actor Artificier. Le 3c est une
résolution manuelle fiable indépendante de la **connexion** de son joueur ;
ce n'est pas encore une autonomie distribuée si l'Actor Artificier est supprimé
ou si un joueur porteur sans droits tente de modifier le registre lui-même.
À terme, matérialiser un état consultable sur la cible pourra prolonger ce modèle,
avec un protocole de synchronisation clair pour éviter deux sources d'autorité.

# P2.11c.1c — Création atomique des liens classe/sous-classe

## Symptôme

Foundryborne échouait dans `DHClass._preUpdate()` :

`The Set#map operation illegally modified the size of the set`

La pile passe par `addLinkedItemsDiff`, donc l'erreur arrive lors de la mise à
jour de `system.features` sur une classe déjà créée.

## Cause

P2.11c.1b créait d'abord l'Artificier avec une collection de features vide,
puis faisait un `classDoc.update({"system.features": ...})`.

Foundryborne gère lui-même le diff des linked items pendant `_preUpdate`.
Modifier toute la collection dans cette phase provoque une mutation du Set
qu'il est justement en train d'itérer.

## Correctif

Les références sont désormais résolues **avant** la création du document :

1. créer les documents `dh-features`;
2. construire les ItemLinks depuis les specimens valides du Toolkit;
3. injecter `system.features` dans les données brutes de l'Artificier;
4. créer l'Artificier une seule fois avec ses liens déjà présents;
5. faire la même chose pour chaque sous-classe, y compris `linkedClass`.

Aucun `DHClass.update()` / `DHSubclass.update()` n'est utilisé pour le linkage
initial.

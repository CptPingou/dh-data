# P2.10h.2 — Retour partiel Backpack → Actor

Objectif :
réutiliser l'action existante **Retour au personnage** sans réécrire le
renderer d'expédition ni le mécanisme de reconstruction des Items Foundry.

## Comportement

Si une entrée du backpack possède une quantité supérieure à 1 :

1. demander la quantité à rendre ;
2. refuser `0` ou toute valeur négative ;
3. borner une valeur supérieure au stock à la quantité disponible ;
4. exécuter le `unloadToActor()` existant sur la quantité choisie ;
5. restaurer dans le backpack la même entrée avec le reliquat.

Exemple :

```text
Backpack : Potion ×5
Retour au personnage : 2

Actor    : Potion ×2 créée par le chemin existant
Backpack : Potion ×3
```

Le chemin complet reste inchangé si toute la quantité est rendue.

## Pourquoi patcher l'API

Le retour complet est déjà GREEN et sait reconstruire un Item Foundry à
partir du snapshot lorsqu'il n'existe plus de source native.

P2.10h.2 entoure donc cette API au lieu de dupliquer sa logique.

## Hors scope

- fusion des stacks côté Actor ou Backpack : P2.10h.3 ;
- autorité multi-client / caravane : P2.10k ;
- transaction généralisée et rollback : P2.10h.5.

# P2.10k.4a — Refresh MJ et conservation de vue

Correctif ciblé après validation de P2.10k.4.

## Corrigé

- Après une requête de transfert joueur validée automatiquement par le MJ,
  la fenêtre du MJ recharge maintenant explicitement le manifest persistant.
  Le MJ ne dépend plus de son propre paquet socket, qu'il ignore volontairement.
- Lorsqu'une fenêtre d'expédition doit être reconstruite, le Toolkit mémorise :
  - le conteneur actuellement sélectionné ;
  - l'onglet actif (`Inventaire` ou `MJ`).
- Après reconstruction, ces deux états sont restaurés.

La validation MJ reste automatique : aucun popup de confirmation n'est ajouté.

## Test

1. MJ : ouvrir le paquetage et rester sur l'onglet **MJ**.
2. Joueur : déplacer un objet **Sol → son sac**.
3. Attendu :
   - l'objet disparaît du Sol côté MJ ;
   - le nouvel état est visible sans action manuelle ;
   - la fenêtre MJ reste sur l'onglet **MJ**.
4. MJ : sélectionner un conteneur précis dans Inventaire puis provoquer un autre refresh.
5. Attendu : le même conteneur reste sélectionné.

# P2.11d.3d — Infusions, autorité mondiale

## Décision

Le registre d'infusions est un **setting world** non exposé dans les paramètres (`daggerheart-campaign-toolkit.activeInfusions`). Une entrée distincte existe pour chaque infusion active (`entries[]`), identifiée par `id`, et l'ordre de création est global. Il n'est plus nécessaire de maintenir un Actor Artificier dans le répertoire PJ pour héberger la mécanique.

Le créateur est une identité logique (`creatorKey`, exemple `atelier:giovanni`) avec un niveau explicite (`sourceLevel`) au moment de la création. Sa capacité connue est enregistrée dans `creatorSlots`. La cible physique est un Actor permanent `targetActorUuid` et son Item `itemId`. Les incidents se résolvent avec **le porteur seul**, que l'Artificier soit déconnecté, absent du canvas ou même absent du répertoire.

Les mutations du setting sont réservées au MJ; le setting peut être lu par les clients joueurs. Aucun bonus mécanique non documenté, aucun hook critique/repos présumé. Les effets restent des instructions manuelles pour HP/Stress/Hope. `effect:null` réserve la mécanique future sans l'inventer.

## IMPORTANT : mise en service et migration

Le nouveau `main.mjs` enregistre le setting lors de `init`. **Redémarrer complètement Foundry** après déploiement (Ctrl+F5 côté client après redémarrage serveur). Le code ne migre jamais en douce les flags des Actors existants. Pour importer les données de 3a/3b/3c, utiliser côté MJ, UNE FOIS :

```js
const { artificerInfusionApi: inf } = await import(
  `/modules/daggerheart-campaign-toolkit/scripts/artificer-infusion-runtime.mjs?v=${Date.now()}`
);
await inf.migrateLegacyInfusions({confirmed:true});
console.table(inf.status().entries);
```

La migration est idempotente et conserve les anciens flags comme sauvegarde. Une fois migrés, ceux-ci ne sont plus autorités. Pour une création entièrement sans Actor Artificier :

```js
await inf.addWorld({
  creatorKey: 'atelier:giovanni',
  creatorName: 'Giovanni',
  sourceLevel: 1,
  targetActorUuid: 'Actor.ID_DU_PORTEUR',
  itemId: 'ID_DE_L_EQUIPEMENT',
});
console.table(inf.status().entries);
```

La capacité est calculée selon le niveau 1/3/5/7/9 → 2/4/6/8/10. `creatorKey` stable permet d'ajouter plusieurs infusions au même fabricant virtuel.

Pour un Artificier **réel** au moment de la fabrication, `inf.add(artificer, porteur, itemId)` reste compatible, mais sa présence n'est pas nécessaire à l'exécution.

Pour résoudre un incident sans Artificier :

```js
const porteur = game.actors.get('ID_DU_PORTEUR');
inf.newestForRecipient(porteur);
await inf.resolveCriticalDamage(porteur, {confirmedCriticalDamage:true, dieResult:2});
```

Le MJ doit avoir confirmé un critique ayant causé des dégâts et fourni le d6 réel. Le résultat 2 retourne `mark-1-hp-manually` sans modifier les champs natifs. Résultat 1 retire la dernière infusion sur ce porteur.

Pour une nouvelle session : `await inf.startNewSession({confirmed:true})`.
Pour le repos long collectif confirmé : `await inf.clearAtLongRest({confirmed:true})` (efface toutes les infusions mondiales). La variante héritée `clearAtLongRest(artificer, {confirmed:true})` ne supprime que celles de ce créateur.

## Limites

- Un GM est nécessaire pour écrire dans le registre du monde. Les joueurs peuvent utiliser leur objet normalement, sans Artificier connecté.
- Les infusions sont un registre mécanique mondial, **pas encore des ActiveEffects sur Item**. Aucun bonus n'a été inventé.
- Les infusions existantes dans le flag 3c doivent être migrées **avant** de créer de nouvelles infusions avec le nouveau système.

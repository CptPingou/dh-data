# P2.11c.1 — Import Artificier + Artillery

## Périmètre

Le jalon importe dans les compendiums Toolkit :

- domaine runtime `artillery`
- 9 Domain Cards Artillery (niveaux 1 à 4)
- classe `Artificier`
- sous-classe `Armurier`
- sous-classe `Forgeron de bataille`
- 10 features liées dans `dh-features`

Les mécaniques restent textuelles : aucune automation Foundry n'est inventée.

## Décision de homebrew

La page web Artificer fournie affiche `Codex + MagiTech`, alors que la fiche
Giovanni utilise `Codex + Artillery`.

Pour **notre** intégration, la classe est explicitement fixée à :

`Codex + Artillery`

Cette divergence reste tracée dans les flags de la classe.

## Icône Artillery

P2.11c.1 utilise temporairement :

`icons/svg/hazard.svg`

On remplacera ce placeholder par l'icône Artillery custom dans un micro-jalon
dédié, sans bloquer le rail de données.

## Workflow

Vérification source :

```powershell
cd C:\dev\dh-data

powershell -ExecutionPolicy Bypass `
  -File ".\tools\verify-p2.11c.1.ps1"
```

Après GREEN, robocopy habituel puis **rechargement complet de Foundry**.

Le boot doit contenir, avant `| init` :

```text
daggerheart-campaign-toolkit | Artillery domain registered
```

Console MJ :

```js
const hb = await import(
  `/modules/daggerheart-campaign-toolkit/scripts/pilot-import.mjs?v=${Date.now()}`
);

await hb.importArtificerArtillery();
```

Puis :

```js
await hb.artificerArtilleryStatus();
```

- `features.expected: 10`
- `features.actual: 10`

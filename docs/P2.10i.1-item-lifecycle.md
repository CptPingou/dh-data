# P2.10i.1 — Lifecycle des entrées d'inventaire

## États

Le lifecycle v1 définit cinq états :

- `active`
- `consumed`
- `modified`
- `deleted`
- `legacy`

## Règle legacy

Les anciennes entrées sans `itemRef.lifecycle` sont considérées `legacy`.

Elles restent utilisables : le snapshot existant continue de permettre le
retour vers l'Actor. Elles peuvent être adoptées explicitement via
`migrateLegacy()`.

## Nouvelles entrées

`foundryItemRef()` écrit désormais :

```js
lifecycle: {
  version: 1,
  state: "active",
  revision: 1
}
```

## API

```js
api.expeditionItems.lifecycleStatus(manifest, { containerId, entryId })
api.expeditionItems.setLifecycle(manifest, { containerId, entryId, state, note })
api.expeditionItems.migrateLegacy(manifest, { containerId, entryId, note })
api.expeditionItems.scanLifecycle(manifest)
```

## États terminaux

`consumed` et `deleted` sont terminaux pour le retour vers l'Actor :
`unloadToActor()` les refuse.

`active`, `modified` et `legacy` restent utilisables.

## Important

L'absence du document UUID d'origine ne signifie pas `deleted`.

Lors d'un transfert Actor -> Backpack, l'Item Actor est normalement supprimé,
donc son UUID devient volontairement non résolvable. Le snapshot reste la
copie transportable de l'objet.

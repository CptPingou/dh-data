# P2.11d.3b — Infusions interpersonnages

La **source d'autorité reste l'Actor Artificier**, via son flag `daggerheart-campaign-toolkit.artificerInfusions`. On ajoute `targetActorUuid` à chaque infusion et on continue à conserver `itemId`, `itemName`, `order`, `createdAt`, `id`. Les entrées 3a dépourvues de `targetActorUuid` sont relues comme des infusions locales, sans perte des IDs ni de la chronologie.

API :

- `inf.eligibleItems(targetActor)` liste les équipements possibles ;
- `await inf.add(artificer, itemId)` conserve le comportement 3a ;
- `await inf.add(artificer, targetActor, itemId)` cible un autre Actor ;
- `await inf.add(artificer, "Actor.ID", itemId)` est également possible ;
- `inf.status(artificer)`, `inf.newest(artificer)`, `inf.remove`, `inf.clearAtLongRest` restent disponibles.

Les liens supportés ici ciblent les **Actors persistants du répertoire**, pas les Actors synthétiques de Tokens non liés. Un personnage ou objet devenu introuvable reste visible (`targetActorExists:false` / `itemExists:false`) et conserve sa place jusqu'au retrait explicite : pas de transfert implicite ni de purge silencieuse. Pas de mutation de l'Item cible, pas de nouveau bonus, pas encore de hook de repos ou de critique.

## Installation et validation

Depuis `E:\Dev\DH Data`, exécuter `powershell -ExecutionPolicy Bypass -File .\tools\verify-p2.11d.3b.ps1` ; après GREEN, déployer par `robocopy` puis `Ctrl+F5`. **Aucun réimport des compendiums.**

## Test console

Sélectionner le token d'un Artificier ; identifier le personnage cible dans `game.actors` :

```js
const { artificerInfusionApi: inf } = await import(
  `/modules/daggerheart-campaign-toolkit/scripts/artificer-infusion-runtime.mjs?v=${Date.now()}`
);
const artificer = canvas.tokens.controlled[0]?.actor;
const targets = game.actors.contents.filter(a => a.id !== artificer?.id);
console.table(targets.map(a => ({ id:a.id, uuid:a.uuid, name:a.name })));
const target = game.actors.get("ID_DU_PERSONNAGE_CIBLE");
console.table(inf.eligibleItems(target));
await inf.add(artificer, target, "ID_EQUIPEMENT_CIBLE");
console.table(inf.status(artificer).entries);
```

Après `F5`, recharger le module, reprendre `artificer` et vérifier `targetActorUuid`, `itemExists:true`, `order`. Pour libérer uniquement l'infusion de test :

```js
await inf.remove(artificer, inf.newest(artificer).id);
```

Si les deux infusions de la phase 3a sont toujours actives, libérer **une place volontairement** avant ce test : le plafond niveau 1 demeure 2. Ne pas appeler `clearAtLongRest` pour un simple test.

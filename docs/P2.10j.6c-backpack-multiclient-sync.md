# P2.10j.6c — Synchronisation multi-client du dépôt

Le Hook Foundry `daggerheart-campaign-toolkit.expeditionChanged` est local au
client. Il ne suffisait donc pas à faire connaître immédiatement au client
joueur un dépôt ou une récupération effectué par le MJ.

## Correction

Le module utilise maintenant son canal socket :

`module.daggerheart-campaign-toolkit`

Après sauvegarde d'un changement d'administration de backpack, le client MJ
diffuse :

- expeditionId
- revision
- containerId
- sourceUserId

Les autres clients :

1. rechargent le manifest persistant ;
2. reconstruisent leur fenêtre d'expédition si elle est ouverte ;
3. réappliquent la vue joueur.

Un backpack dont `presentation.accessState === "stored"` disparaît donc
immédiatement de la vue joueur.

Le menu Actor `Mettre dans le sac à dos` conserve également la garde ajoutée en
j.6a : un joueur ne peut pas charger un item dans un backpack déposé.

## Portée

C'est une synchronisation ciblée de l'état des backpacks. L'autorité complète
des transferts inter-clients reste une étape P2.10k distincte.

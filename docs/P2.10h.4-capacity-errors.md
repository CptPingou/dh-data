# P2.10h.4 — Capacité et erreurs propres

## Principe

Les `reason` internes restent inchangés pour le debug.

Exemple :

```js
{
  unloaded: false,
  reason: "quantity-exceeds-entry",
  userMessage: "La quantité demandée dépasse la quantité disponible."
}
```

La traduction utilisateur est centralisée dans :

```text
scripts/expedition-errors.mjs
```

## Messages couverts

- quantité invalide ;
- quantité supérieure au stock ;
- entrée disparue ;
- Actor introuvable ;
- snapshot / Item Foundry non résolu ;
- création de l'Item Foundry impossible ;
- capacité pleine ;
- aucun slot libre ;
- slot déjà occupé ;
- conteneur source ou destination introuvable.

Les raisons déjà rédigées pour un humain restent utilisables.

## Actor → Backpack

L'UI ne masque plus la raison réelle derrière le message générique
"Impossible de mettre X dans le sac à dos".

Le log console conserve l'erreur technique, tandis que la notification
utilisateur passe par `expeditionErrorMessage()`.

## Backpack → Actor

`unloadToActor()` expose maintenant `userMessage` en plus de `reason`.

Cela prépare les futures UI (caravane, échanges MJ, multi-PJ) sans
dupliquer la table de traduction.

## Invariant

La logique métier h.1 / h.2 / h.3 n'est pas modifiée.

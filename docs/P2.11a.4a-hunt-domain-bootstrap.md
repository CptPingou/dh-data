# P2.11a.4a — Bootstrap du domaine Chasse

## Problème

Après la migration des cartes Monster Hunter vers `system.domain = "hunt"`,
les cartes déjà embarquées sur un Actor sont validées pendant le chargement
du monde.

Le domaine `hunt` était jusqu'ici enregistré par le pilote/import runtime,
donc trop tard pour cette validation.

Symptôme :

`domain: hunt is not a valid choice`

## Correctif

`registerHuntDomain()` est désormais défini à côté du domaine contextuel
legacy `hunting` dans `hunting-domain-card-bridge.mjs`.

`main.mjs` l'appelle pendant l'évaluation du module, exactement comme le
bootstrap `blood`, donc avant `Hooks.once("init")` et avant la préparation
des documents persistés par Foundry.

Le hook `init` garde un fallback si le bootstrap précoce n'a pas pu
s'exécuter.

Les deux domaines restent distincts :

- `hunt` : vrai domaine Chasse des Domain Cards Monster Hunter ;
- `hunting` : domaine contextuel historique/technique utilisé par le bridge.

# P2.10h.3 — Fusion des stacks identiques

## Objectif

Deux transferts successifs du même objet doivent produire un seul stack,
et non plusieurs entrées séparées.

La fusion s'applique dans les deux sens :

```text
Actor -> Backpack
Backpack -> Actor
```

## Identité de stack

La fusion n'utilise pas le nom seul.

Deux objets fusionnent seulement si :

1. leur source est la même ;
2. un snapshot est disponible ;
3. les snapshots sont mécaniquement identiques après suppression des
   champs volatils :
   - `_id`
   - `_stats`
   - `sort`
   - `folder`
   - `system.quantity`
   - `system.amount`

Cela évite de fusionner par erreur deux armes du même modèle ayant des
modifications différentes.

Les anciennes entrées sans snapshot ne sont pas fusionnées
automatiquement.

## Backpack

La recherche du stack existant est effectuée avant le preflight de
capacité.

Conséquence importante :

```text
Backpack 8/8
Potion ×2 déjà présente
+ Potion ×1 identique
=> Potion ×3
=> reste 8/8
```

Le transfert n'est donc pas rejeté faute de slot lorsqu'il peut rejoindre
un stack existant.

## Actor

Au retour vers le personnage :

- si un Item mécaniquement identique existe déjà et possède
  `system.quantity` ou `system.amount`, sa quantité est augmentée ;
- sinon l'Item est créé comme auparavant.

Si l'extraction du manifest échoue après la fusion Actor, la quantité
Actor est restaurée à sa valeur précédente.

## Hors scope

- limites maximales de stack éventuelles ;
- règles spéciales de stack par type d'objet ;
- transferts caravane / inter-PJ : P2.10k.

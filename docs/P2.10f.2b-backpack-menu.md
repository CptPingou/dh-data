# P2.10f.2b — menu « Mettre dans le sac à dos »

## Règle d'architecture

`E:\Dev\DH Data` est la source d'autorité.

La copie :

`E:\FoundryvttDataV14\Data\modules\daggerheart-campaign-toolkit`

est uniquement une cible de déploiement.

P2.10f.2b n'est valide que si :

1. `scripts/item-backpack-menu.mjs` existe dans **DH Data** ;
2. `scripts/main.mjs` contient exactement :

```js
import "./item-backpack-menu.mjs";
```

3. ces modifications sont commitées dans le dépôt ;
4. après robocopy, `tools/verify-p2.10f.2b.ps1` retourne `P2.10f.2b GREEN`.

Il n'y a donc plus de procédure `apply-source.ps1` à conserver.

## Contrôle après checkout / nouveau PC

Depuis n'importe quel PowerShell :

```powershell
powershell -ExecutionPolicy Bypass -File "E:\Dev\DH Data\tools\verify-p2.10f.2b.ps1"
```

Le script contrôle :

- présence du hook dans la source ;
- import du hook par `scripts/main.mjs` ;
- présence des primitives attendues ;
- si la cible Foundry existe, égalité SHA-256 entre la source et la copie déployée.

## Critère GREEN

Le développement n'est pas considéré terminé tant que le contrôle n'affiche pas :

```text
P2.10f.2b GREEN
```

Ainsi un checkout sur un PC neuf révèle immédiatement une intégration perdue avant le lancement de la partie.

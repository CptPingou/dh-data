# P2.11d.3e — Cycle de vie du registre mondial

3d possédait déjà `resolveCriticalDamage`, `startNewSession` et `clearAtLongRest` sur le registre mondial. 3e conserve cette autorité, teste les cas multifa­bricants et ajoute deux sécurités :

- `clearForRecipientAtLongRest(porteur, {confirmed:true})` supprime uniquement les infusions portées par le personnage en repos long, tous créateurs confondus ; les autres personnages et leurs infusions restent intacts. Le repos long **collectif** explicite reste `clearAtLongRest({confirmed:true})`. Ne pas appeler ce dernier pour le repos d'un seul personnage.
- `incidentKey` optionnel pour `resolveCriticalDamage` : une clé identifiant un événement critique dans la session empêche de le traiter deux fois, y compris après rechargement. Une clé distincte est nécessaire pour chaque critique. Sans clé, compatibilité conservée avec 3d mais sans protection contre la répétition manuelle.

La prévention pour 1 Espoir reste **une fois par session et par porteur** : la dépense de l'Espoir doit être faite sur sa fiche native, puis confirmée par `{prevent:true, confirmedHopeSpent:true}`. Les jets sont donnés explicitement par le MJ (`dieResult:1..6`). Résultats : 1 = perte de l'infusion la plus récente du porteur, 2 = marquer 1 PV manuellement, 3 = marquer 1 Stress manuellement, 4–6 = rien. Aucune écriture sur la fiche native n'est improvisée. La nouvelle session vide les clés traitées et la prévention, sans supprimer les infusions.

Le fabricant n'est jamais requis au moment de l'incident ; la donnée est dans `world.activeInfusions`. `effect:null` reste inchangé. Pas d'ActiveEffect inventé, pas de hook natif supposé.

## Test Foundry MJ non destructif

Ne pas tester la suppression en utilisant les deux infusions actives que vous souhaitez conserver : la suppression sur `dieResult:1` et le repos long modifient réellement le setting monde.

```js
const { artificerInfusionApi: inf } = await import(
  `/modules/daggerheart-campaign-toolkit/scripts/artificer-infusion-runtime.mjs?v=${Date.now()}`
);
const porteur = game.actors.get('Ald8tw3yt5TLle8N'); // test1, à ajuster si besoin
({ version:inf.version, before:inf.status(), newest:inf.newestForRecipient(porteur) });
```

Pour un essai sans supprimer une infusion : utiliser le `dieResult:4` et une clé inédite (dans une session de test, et seulement après validation du MJ qu'il simule un critique) :

```js
await inf.resolveCriticalDamage(porteur, {
  confirmedCriticalDamage: true, dieResult: 4, incidentKey: 'test-crit-001'
});
```

Répéter la même commande doit être refusé ; `inf.status().entries` reste inchangé. Les essais de repos long ciblé sont destructifs : les faire uniquement quand on souhaite vraiment faire expirer les infusions du porteur ou sur un monde de test sauvegardé.

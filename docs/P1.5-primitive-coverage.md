# P1.5 — Primitive Coverage Test

P1.5 tests whether the P1.4 vocabulary can express mechanics without
corpus-specific runtime concepts.

The key independent stress test is Monster Hunter / Chasse v0.4. Its canonical
design explicitly says that Chasse should primarily become content assembled
from primitives rather than a collection of TypeScript subsystems.

The fixture in:

`data/homebrew/monster-hunter/primitive-coverage-input.json`

contains normalized **requirements**, not copied rules prose. It covers:

- Monster Hunter action budget;
- Opener / Finisher / Support;
- Opportunity;
- Engagement resolution;
- targetable anatomy, Fractured/Broken/Severed;
- harvest and materials;
- craft / augments;
- inventory and caravan capacity;
- provisions;
- territory graph;
- FOB modules;
- traps/baits/preparations;
- hunt procedure;
- rest hooks;
- tactical dice modifiers.

A requirement is FULL when every primitive it needs already exists in the
observed P1.4 census.

This deliberately tests **composition**. A novel mechanic is not evidence for a
new primitive when it can already be expressed by combining existing ones.

## Run

From `C:\dev\DH Data>`:

```bat
python tools\test_primitive_coverage.py
```

GREEN means the current vocabulary covers the independent Monster Hunter
fixture and can proceed to P1.6.

RED is useful too: `missing_primitives` identifies exactly where the vocabulary
needs review.

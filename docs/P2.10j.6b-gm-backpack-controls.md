# P2.10j.6b — Stabilisation des contrôles MJ

Cause du défaut j.6a :

Le `MutationObserver` détectait l'injection du panneau d'administration puis
relançait le refresh. Le refresh supprimait et recréait le panneau. Les inputs
perdaient donc leur focus et l'état temporaire des boutons était immédiatement
réinitialisé.

Correction :

- le panneau est réutilisé tant que `expeditionId` + `manifest.revision`
  n'ont pas changé ;
- les mutations internes à `.dhct-backpack-admin-panel` sont ignorées ;
- les contrôles arrêtent la propagation vers le formulaire/dialog parent ;
- `Déposer` active le champ de lieu et lui donne le focus ;
- `Enregistrer` persiste puis laisse le refresh réel se produire après save.

Aucune modification du modèle de données de j.6a.

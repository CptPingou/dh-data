# P2.10h.5 — Rollback transactionnel

## Objectif

Un transfert ne doit jamais laisser Actor et manifest dans deux états
différents si une exception survient après une mutation.

## Snapshot

Avant mutation :

- snapshot complet du manifest ;
- snapshot des Items de l'Actor concerné.

## Rollback

En cas d'exception dans `loadFromActor()` ou `unloadToActor()` :

1. restauration du manifest en mémoire ;
2. restauration de l'inventaire Actor ;
3. journalisation d'un éventuel échec de rollback ;
4. propagation de l'erreur d'origine.

Le rollback complète les compensations locales déjà présentes dans h.1-h.3.

## Limite volontaire

Cette étape protège la transaction logique locale Actor + manifest.

La synchronisation multi-client et l'autorité MJ sur la caravane restent
dans P2.10k.

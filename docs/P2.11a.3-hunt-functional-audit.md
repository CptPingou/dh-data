# P2.11a.3 — Audit fonctionnel du domaine Chasse

Ce jalon est **lecture seule** : il n'altère aucune carte.

Il audite les 17 cartes Monster Hunter présentes dans :

`data/homebrew/monster-hunter/dh-domain-cards.json`

et génère trois rapports :

- `reports/p2.11a.3-hunt-audit/hunt-audit.md`
- `reports/p2.11a.3-hunt-audit/hunt-audit.csv`
- `reports/p2.11a.3-hunt-audit/hunt-audit.json`

Le rapport extrait pour chaque carte :
- nom et `_id` ;
- domaine ;
- niveau ;
- Recall Cost ;
- type ;
- rôle estimé : Opener / Finisher / Support / Utilitaire ;
- nombre et types d'Actions Foundryborne ;
- nombre d'Active Effects ;
- présence explicite de termes runtime Monster Hunter / Opportunity / Hope / Fear ;
- description complète dans les exports JSON/CSV.

## Lancer

```powershell
cd C:\dev\dh-data

python .\tools\audit-p2.11a.3-hunt.py --root .
```

Puis :

```powershell
powershell -ExecutionPolicy Bypass `
  -File ".\tools\verify-p2.11a.3.ps1"
```

Le vérificateur exige 17 cartes et 17/17 dans `hunt`.

Une fois GREEN, colle ici le contenu de :

`reports\p2.11a.3-hunt-audit\hunt-audit.md`

On pourra alors faire l'audit de design réel : couverture Opener / Finisher /
Support, automatisations manquantes, doublons fonctionnels et niveaux à créer
pour passer du prototype actuel au domaine complet.

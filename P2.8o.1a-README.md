# P2.8o.1a — Actor-scoped Hunt manager

Correctif ciblé du gestionnaire Chasse.

## Cause
Le sélecteur de cartes utilisait en dernier recours :

```js
canvas.tokens.controlled[0]?.actor
```

Le bouton Chasse pouvait donc ouvrir le loadout du token sélectionné au lieu du
personnage propriétaire de la fiche ayant ouvert le sélecteur.

## Correction
- suppression totale du fallback vers le token contrôlé ;
- résolution de l'Actor uniquement depuis la chaîne de propriété de
  l'ApplicationV2 (`app`, `parent`, `options`) ;
- si aucun Actor propriétaire ne peut être établi, le bouton n'est pas injecté
  et un warning diagnostic est écrit dans la console plutôt que d'agir sur le
  mauvais personnage.

## Validation
1. sélectionner éventuellement le token `test`;
2. ouvrir la fiche `test2`;
3. ouvrir le chooser `+`;
4. cliquer `Chasse`;
5. le manager doit afficher `Cartes Chasse — test2` et `0/2`.
6. `test` doit toujours afficher `2/2`.
